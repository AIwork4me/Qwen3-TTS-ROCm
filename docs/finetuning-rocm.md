# Fine-tuning on ROCm — execution-validation record (2026-09-20; upstream-fix status updated 2026-09-21)

This page documents that the **official Qwen3-TTS fine-tuning workflow
executes end-to-end on the validated AMD ROCm stack** of this repository:
dataset preparation → short training run → per-epoch checkpoint save →
reload of the saved checkpoint through the official path → synthesis that
passes waveform sanity checks.

> **Scope — EXECUTION VALIDATION, not convergence.** Nothing on this page is
> a quality claim. The training corpus is a tiny synthetic set generated by
> the official model itself; the run exercises mechanics (data plumbing,
> optimizer steps, checkpoint write/read, post-finetune inference), not
> modelling quality. See [NOT PROVEN](#not-proven) for the explicit list.

Evidence package: [`evidence/finetune-smoke-2026-09-20.txt`](../evidence/finetune-smoke-2026-09-20.txt)
(full machine-generated transcript, phase-marked) and
[`evidence/finetune-smoke-2026-09-20.json`](../evidence/finetune-smoke-2026-09-20.json)
(structured facts; line numbers below refer to the `.txt`).

`api.github.com` and `codeload.github.com` stayed reachable. The clone was
therefore bootstrapped as:

1. **SHA re-verified** via `api.github.com/repos/QwenLM/Qwen3-TTS/commits/HEAD`

2. **Content** from `codeload.github.com/.../tar.gz/022e286b...`
   (sha256 `c7129dc1…`); all 37 blobs re-hashed with `git hash-object` and
   matched against the API's recursive tree listing (line 47).
3. **Git metadata rebuilt** from the API: the reconstructed tree hash equals
   `33e4644d…` and the reconstructed commit object (from the API's
   `verification.payload`, tz `+0800`, including the gpgsig header) hashes to
   **exactly the pinned SHA**, so `git -C .upstream/Qwen3-TTS rev-parse HEAD`
   reports the upstream SHA itself. The repo behaves as a shallow checkout at
   that commit (git's SHA check is the authenticity proof).

If `github.com` is reachable for you, the plain equivalent is:

## ⚠️ Disclosed upstream-defect workaround: hard-coded `flash_attention_2`

`sft_12hz.py` hard-codes `attn_implementation="flash_attention_2"` at line 51.
The validated ROCm wheel stack ships no flash-attn build, so the **official
script fails at model init as shipped** (transcript line 1545, verbatim):

```
ImportError: FlashAttention2 has been toggled on, but it cannot be used due
to the following error: the package flash_attn seems to be not installed. [...]
```

Workaround applied for the smoke run (per the program's orchestrator ruling):

1. The script was run **AS-IS first** to capture that failure verbatim.
2. A **single-line override inside the gitignored `.upstream` clone** was
   applied — `attn_implementation="flash_attention_2"` → `"sdpa"` — with the
   exact one-line diff recorded in the transcript (lines 1553–1567).
3. After training and reload, the clone was restored pristine:
   `git -C .upstream/Qwen3-TTS checkout -- .`; `git status --porcelain` is
   empty and HEAD is back at the pinned SHA (lines 1647–1654) — the
   zero-patch audit passes.

**No upstream code exists anywhere in this repository.** The override lived
only in the gitignored clone during the run.

> **Upstream issue filed (2026-09-21):**
> [QwenLM/Qwen3-TTS#372](https://github.com/QwenLM/Qwen3-TTS/issues/372) —
> `finetuning/sft_12hz.py` hard-codes `attn_implementation="flash_attention_2"`,
> which blocks every flash-attn-less stack, including the whole validated AMD
> ROCm wheel stack this project targets. The issue quotes the failure verbatim
> from our smoke transcript, asks for a CLI-selectable attention implementation
> or an automatic `sdpa` fallback (mirroring the inference path), and offers
> both PR options (gh capture: `evidence/upstream-issue-2026-09-21.txt`).
> Follow-up, same day: the CLI-selectable option was submitted as
> [PR #373](https://github.com/QwenLM/Qwen3-TTS/pull/373) — see
> [Upstream fix status](#upstream-fix-status) below.

## Reproduction

### 1) Build the self-generated dataset (4A)

```bash
# 12 utterances (6 zh + 6 en) + 1 shared reference clip, rendered by the
# OFFICIAL 1.7B CustomVoice model (speaker 'serena'), torch.manual_seed(1234)
# before each render, max_new_tokens=512, verbatim transcripts.
.venv/bin/python scripts/make_finetune_dataset.py
# -> .work-finetune/data/{ref_speaker.wav, utt_*.wav, train_raw.jsonl,
#    dataset_report.txt}
```

* Manifest: [`tests/data/finetune_manifest.json`](../tests/data/finetune_manifest.json)
  (12 original short sentences, distinct from `tests/data/multilingual_samples.json`).
* Generator: [`scripts/make_finetune_dataset.py`](../scripts/make_finetune_dataset.py).
* **Self-generated speech only** — no third-party audio enters the workflow.
* JSONL schema = upstream `prepare_data.py`'s input contract: one object per
  line with `audio` / `text` / `ref_audio` (same `ref_audio` for all samples,
  per the upstream README).

### 2) Official data preparation (4B)

```bash
(cd .upstream/Qwen3-TTS/finetuning && \
 /path/to/repo/.venv/bin/python prepare_data.py \
   --device cuda:0 \
   --tokenizer_model_path /path/to/models/Qwen3-TTS-Tokenizer-12Hz \
   --input_jsonl  /path/to/.work-finetune/data/train_raw.jsonl \
   --output_jsonl /path/to/.work-finetune/data/train_with_codes.jsonl)
```

Ran **AS-IS, exit 0** → 12 lines each carrying `audio_codes`
(26–45 frames × 16 codebooks). Transcript lines 1462–1501.

### 3) Training smoke (4C)

The AS-IS invocation fails on flash-attn (above). With the single-line `sdpa`
override in the clone, training was driven through a small launcher
(`.work-finetune/run_sft_launcher.py`, gitignored) that imports the upstream
module and calls its `train()` **verbatim**, so `torch.cuda` peak-memory
stats could be read from the actual training process:

```bash
.venv/bin/python .work-finetune/run_sft_launcher.py \
  --init_model_path   models/Qwen3-TTS-12Hz-1.7B-Base \
  --output_model_path .work-finetune/runs/smoke \
  --train_jsonl       .work-finetune/data/train_with_codes.jsonl \
  --batch_size 2 --lr 2e-5 --num_epochs 2 --speaker_name smoke_speaker
```

(`batch_size` and `lr` are the script's own defaults. The smallest
officially-supported configuration that still exercises a checkpoint save
was chosen: 12 samples, batch 2, 1.7B Base — the preferred model; the 0.6B
fallback was not needed.)

### 4) Checkpoint reload + synthesis (4D)

```bash
.venv/bin/python .work-finetune/reload_check.py   # gitignored scratch script
```

Follows the upstream README §4 path — `Qwen3TTSModel.from_pretrained(
<checkpoint dir>, bf16)` then `generate_custom_voice(text, speaker=…)` —
invoked through `qwen3_tts_rocm.loader.load`, whose HIP smart default is
attention `sdpa` (the README example's literal `flash_attention_2` would hit
the same ImportError documented above).

## What was run

| Fact | Value |
|---|---|
| Model | Qwen3-TTS-12Hz-1.7B-Base, **bf16** (hard-coded by the script) |
| Dataset | 12 self-generated utterances (6 zh + 6 en), 2.1–3.6 s each |
| Batch size / lr | 2 / 2e-5 (upstream defaults) |
| Sequence sizes | 26–45 codec frames (×16), 13–55 text chars (no length-limit args exist upstream) |
| Optimizer steps | **12** (6 per epoch × 2 epochs — the script steps per microbatch) |
| Wall time | **19.0 s** `train()` (24.3 s full process) — far under the 60-min budget |
| Peak GPU memory | `torch.cuda.max_memory_allocated` **18.02 GiB** (reserved 18.49 GiB) |
| Checkpoints | `.work-finetune/runs/smoke/checkpoint-epoch-{0,1}` (3.83 GB each, gitignored) |
| Loss (verbatim, script's own log) | `Epoch 0 \| Step 0 \| Loss: 13.6470` · `Epoch 1 \| Step 0 \| Loss: 15.0211` |
| Reload synthesis | speaker `smoke_speaker` (id 3000), 6.1 s, 24 kHz, 3.52 s clip, peak 0.2158, rms 0.0378 — `assert_wav_sane` PASS |

A note on the step count: upstream's `sft_12hz.py` calls
`optimizer.step()`/`zero_grad()` on **every microbatch** (the calls are not
gated on `accelerator.sync_gradients`, despite
`gradient_accumulation_steps=4`), so 12 samples at batch 2 give 6 optimizer
steps per epoch — 12 for two epochs. This is upstream behavior, recorded
as-found; the loss lines above are the script's own prints (`step % 10 == 0`).

## PROVEN

Each item is linked to the evidence transcript
(`evidence/finetune-smoke-2026-09-20.txt`, line numbers).

1. **Self-generated dataset builds** — 12 + 1 renders, all sane, upstream
   JSONL schema (lines 248–1460; generator exit 0).
2. **Official preprocessing works on ROCm** — upstream `prepare_data.py`
   AS-IS, exit 0, `audio_codes` for all 12 lines (lines 1462–1501:
   `prepare-exit=0`, `SCHEMA-OK`).
3. **Training runs 12 optimizer steps on the real GPU** — bf16 Accelerator
   loop on gfx1151; loss lines verbatim (lines 1593–1594), wall 19.0 s
   (line 1595), peak 18.02 GiB (line 1597).
4. **Checkpoints save** — `checkpoint-epoch-0/1` written per epoch,
   converted to CustomVoice format (`tts_model_type: custom_voice`,
   `spk_id {smoke_speaker: 3000}`, transcript lines 1627–1644 + dir listing
   1610–1624).
5. **Checkpoint reloads through the official path** —
   `Qwen3TTSModel.from_pretrained(checkpoint-epoch-1)` OK; supported
   speakers after reload: `['smoke_speaker']` (lines 1633–1634).
6. **Post-finetune inference produces a sane waveform** —
   `generate_custom_voice` on a manifest sentence: finite, 24 kHz, 3.52 s,
   non-silent (rms 0.038), `assert_wav_sane` PASS, `RELOAD-AND-SYNTHESIS-OK`
   (lines 1635–1638).

## NOT PROVEN

* **Speaker-similarity quality** — no embedding-distance or MOS-style
  evaluation was run; "sane audio" is a structural check only.
* **Convergence quality** — 12 steps on 12 synthetic clips; the loss values
  are quoted verbatim with **no interpretation**.
* **Optimal hyperparameters** — batch 2 / lr 2e-5 are upstream defaults,
  chosen for smoke speed, not tuned.
* **Long-run stability** — no multi-hour, multi-epoch, grad-accumulation or
  OOM-behaviour study.
* **Multi-speaker training** — upstream documents single-speaker SFT only;
  not attempted.
* **Production scalability** — dataset size, throughput and disk
  (≈3.9 GB/checkpoint) were not stress-tested.

## Limitations

* The corpus is **synthetic and self-generated** (rendered by the official
  1.7B CustomVoice model): transcript == manifest text by construction, and
  no human speech is involved. It validates mechanics, not generalization.
* The flash-attn workaround (single-line `sdpa` override) is a **temporary,
  disclosed upstream-defect workaround** inside a gitignored clone; the
  program's no-fork policy is preserved (clone restored pristine, audit
  clean). Upstream issue #372 was filed 2026-09-21 and the fix PR #373
  submitted the same day ([Upstream fix status](#upstream-fix-status));
  until it merges, the workaround remains required for the published
  `qwen-tts==0.1.1`.
* `github.com` inaccessibility forced the disclosed clone-bootstrap
  procedure described above; the pinned SHA is verified by git's own
  content-addressing.
